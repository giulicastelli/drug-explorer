Reading: pid 195 is the killed loader's backend, still 'active' in ClientRead (waiting for COPY data) 5.5 minutes after
docker kill. PostgreSQL never saw the connection close (the container's network went away with it), and
tcp_keepalives_idle = 0 means the OS default (Linux: 2 hours before the first probe). Its transaction holds the
ACCESS EXCLUSIVE lock taken by TRUNCATE, so every reader of labels waits (pid 231 = the state query above;
the dashboard would wait the same way). Nothing was committed, so the data is safe, but not readable.
